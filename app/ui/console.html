Service health

GET /health · GET /discord/health — the bot token itself is set via DISCORD_BOT_TOKEN in the service's environment; this console can only report its state, never view or change it.

Authentication to this API

Every /discord/* endpoint accepts an X-API-Key header or a signed-in Discord session cookie. Neither is required when the server has no API_KEYS configured.

Access requests local only

GET /discord/access-requests

This is an application-level record, not a Discord approval. Discord has no API for a bot to request private-channel access. PENDING means we are waiting for a human Discord server administrator to grant the bot View Channel + Read Message History by hand, re-checked automatically every 12 hours. ACCEPTED means our own re-check found the bot can genuinely read the channel — not that Discord approved anything.

Monitors local only

GET /discord/monitors — a monitor only reaches RUNNING once access is confirmed; on a private channel it parks in WAITING_FOR_ACCESS until an admin grants permission.

Search stored messages local only

POST /discord/search — Discord provides no cross-server search API for bots; this searches only what has already been collected via scrape or live monitoring.

Find a server by name hits Discord

GET /discord/guilds/search — only searches servers the bot is already in.

Find a channel by name

GET /discord/channels/search — reads channels already discovered into SQLite. Add a guild id and tick refresh to discover as part of the search.

Invite the bot to a server

Adding a bot to a server is a Discord-native OAuth2 action a human must complete — no API call can do it. A human being a member of a server does not grant the bot access; the bot must be independently authorized.

Open Discord invite link
Only a server admin with “Manage Server” can complete this. The link requests View Channel + Read Message History only — never Administrator.

Notifications local only

GET /discord/notifications — every access-status transition and matched-message event this service recorded. These are the application's own records; it never sends Discord DMs.
